1. В чём разница между `pgx.Connect` и `pgxpool.New`? Когда какой способ подключения использовать?
pgx.Connect дает нам возможность один раз подключится к бд и запросы будут выполнятся по очереди.
А pgxpool.New создает пул этих подключении и выполняет запросы параллельно.
Connect лучше использовать для теста подключения, но для прода этот способ не подходит. Для прода лучше использовать пул.

2. Какой метод использовать для SELECT одной записи, а какой для нескольких? Что вернёт QueryRow, если запись не найдена?
для одной записи QueryRow, для нескольких Query. QueryRow не возвращает ошибку сама по себе, ошибка вернется если мы использовали Scan().

3. Зачем нужны транзакции? Что произойдёт с данными, если между BEGIN и COMMIT произойдёт ошибка?
Транзакции нужны чтобы выполнять несколько запросов безопасно. Если в каком либо запросе произойдет ошибка, произойдет Rollback
который делает откат

4. Почему после `pool.Begin(ctx)` следует делать `defer tx.Rollback(ctx)`? Что произойдёт, если Rollback вызвать после Commit?
Если произойдет ошибка в каком либо запросе, гарантированно сделать откат используя Rollback. Если вызвать Rollback после
Commit, откат не сработает. Потому что мы уже закоммитили и закрыли транзакцию

5. Какие преимущества даёт Repository pattern? Как он помогает в тестировании?
Repository pattern дает возможность отделить работу с бд от других слоев (service, handlers). То есть repository работает исключительно с бд.
Repository в тесте позволяет использовать мок данные, это удобно.
