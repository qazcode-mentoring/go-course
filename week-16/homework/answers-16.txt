В чём разница между t.Error() и t.Fatal()? Когда следует использовать каждый из них?
Оба выводят ошибку, только t.Error() после вывода ошибки продолжает программу/тест, t.Fatal() после ошибки заканчивает программу/тест

Почему table-driven tests считаются идиоматичным подходом в Go? Какие преимущества они дают по сравнению с отдельными тестовыми функциями?
Позволяет писать тесты не повторяясь в условиях теста. В таблице собираются все кейсы, которые нужно проверить и через цикл проверяется каждый

Что такое покрытие кода (code coverage) и почему 100% покрытие не гарантирует отсутствие багов?
code cover показывает процент который был протестирован в исходном коде, то есть какая часть была тронута тестами.
не гарантирует, потому что покрытие всего кода не означает тест всей программы, где-то могут быть пропущены проверки и тд

Как интерфейсы помогают в тестировании? Объясни принцип "accept interfaces, return structs" в контексте мокирования.
Интерфейсы помогают тестить не требуя использования реальных данных или подключения к бд например.
Можно использовать фековые (мок) данные, который ведет себя так, как нужно для тестирования.
Принцип «Accept interfaces» заключается в том, чтобы позволить потребителю определять, что он
хочет видеть в интерфейсе. Потребителю не нужно беспокоиться о том, какая зависимость существует,
ему достаточно того, чтобы интерфейс мог выполнять необходимые ему задачи


Для чего нужен метод t.Helper() и как он влияет на вывод ошибок в тестах?
Это метод который игнорирует текущую функцию при поиске места возникновения ошибки и поднимается на один уровень
выше по стеку вызовов
