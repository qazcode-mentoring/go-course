# ДЗ 14.2: Worker Pool

## Цель
Научиться реализовывать паттерн "пул воркеров" (worker pool) для параллельной обработки задач с ограниченным числом горутин.

## Что нужно сделать

Реализовать пул воркеров, который обрабатывает задачи параллельно с ограниченным количеством горутин. Это важный паттерн, когда нужно обработать много задач, но нельзя создавать неограниченное число горутин.

## Сигнатуры

```go
// Job представляет задачу для обработки
type Job struct {
    ID   int
    Data string
}

// Result представляет результат обработки задачи
type Result struct {
    JobID      int
    Output     string
    WorkerID   int
    Duration   time.Duration
}

// worker обрабатывает задачи из канала jobs и отправляет результаты в канал results.
// Параметры:
//   - id: уникальный идентификатор воркера
//   - jobs: канал с задачами для обработки
//   - results: канал для отправки результатов
//   - wg: WaitGroup для сигнализации о завершении
func worker(id int, jobs <-chan Job, results chan<- Result, wg *sync.WaitGroup)

// processJob обрабатывает одну задачу (симуляция работы).
// Возвращает результат обработки.
func processJob(job Job) string

// RunWorkerPool запускает пул воркеров и обрабатывает задачи.
// Параметры:
//   - numWorkers: количество воркеров в пуле
//   - jobs: слайс задач для обработки
// Возвращает:
//   - слайс результатов обработки
func RunWorkerPool(numWorkers int, jobs []Job) []Result
```

## Теория: Паттерн Worker Pool

Worker pool - это паттерн, при котором фиксированное количество воркеров (горутин) обрабатывает очередь задач. Это позволяет:

1. **Ограничить ресурсы** - не создавать тысячи горутин
2. **Контролировать нагрузку** - на базу данных, внешние API и т.д.
3. **Эффективно использовать CPU** - оптимальное число воркеров = GOMAXPROCS

```
        +----------+
        |  Jobs    |
        | Channel  |
        +----+-----+
             |
    +--------+--------+
    |        |        |
    v        v        v
+-------+ +-------+ +-------+
|Worker1| |Worker2| |Worker3|
+---+---+ +---+---+ +---+---+
    |        |        |
    +--------+--------+
             |
             v
        +----+-----+
        | Results  |
        | Channel  |
        +----------+
```

## Пример использования

```go
func main() {
    // Создаём 10 задач
    jobs := make([]Job, 10)
    for i := 0; i < 10; i++ {
        jobs[i] = Job{
            ID:   i + 1,
            Data: fmt.Sprintf("task-%d", i+1),
        }
    }

    // Запускаем пул из 3 воркеров
    fmt.Println("Запуск пула из 3 воркеров для 10 задач")
    start := time.Now()

    results := RunWorkerPool(3, jobs)

    elapsed := time.Since(start)
    fmt.Printf("\nВсе задачи выполнены за %v\n", elapsed)

    // Выводим результаты
    for _, r := range results {
        fmt.Printf("Job %d: %s (worker %d, %v)\n",
            r.JobID, r.Output, r.WorkerID, r.Duration)
    }
}
```

## Подсказки

- Используй буферизованный канал для jobs с размером равным количеству задач
- Закрой канал jobs после отправки всех задач
- Воркеры должны завершаться, когда канал jobs закрыт (`for job := range jobs`)
- Используй WaitGroup для ожидания завершения всех воркеров
- Результаты можно собирать через отдельный канал

## Бонусное задание

Добавь возможность graceful shutdown - отмену обработки через context:

```go
func RunWorkerPoolWithContext(ctx context.Context, numWorkers int, jobs []Job) []Result
```

При отмене context воркеры должны завершить текущую задачу и прекратить брать новые.

## Критерии выполнения

- [ ] Реализована функция `worker`, которая обрабатывает задачи из канала
- [ ] Реализована функция `RunWorkerPool`, которая запускает пул воркеров
- [ ] Одновременно работает не более `numWorkers` горутин
- [ ] Все задачи обрабатываются
- [ ] Функция возвращает результаты всех обработанных задач
- [ ] Программа корректно завершается (нет утечки горутин)
- [ ] Программа проходит проверку `go run -race`
