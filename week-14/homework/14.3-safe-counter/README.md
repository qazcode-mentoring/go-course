# ДЗ 14.3: Safe Counter

## Цель
Научиться использовать `sync.Mutex` для защиты общих данных от состояния гонки (race condition).

## Что нужно сделать

Реализовать потокобезопасный счётчик, который можно безопасно использовать из нескольких горутин одновременно.

## Сигнатуры

```go
// Counter представляет потокобезопасный счётчик
type Counter struct {
    // TODO: добавь поля
}

// NewCounter создаёт новый счётчик с начальным значением 0
func NewCounter() *Counter

// Increment увеличивает счётчик на 1 и возвращает новое значение
func (c *Counter) Increment() int

// Decrement уменьшает счётчик на 1 и возвращает новое значение
func (c *Counter) Decrement() int

// Add добавляет delta к счётчику и возвращает новое значение
func (c *Counter) Add(delta int) int

// Value возвращает текущее значение счётчика
func (c *Counter) Value() int

// Reset сбрасывает счётчик в 0 и возвращает предыдущее значение
func (c *Counter) Reset() int
```

## Теория: Race Condition

**Race condition** (состояние гонки) - это ситуация, когда несколько горутин одновременно обращаются к общим данным, и хотя бы одна из них изменяет эти данные.

### Пример небезопасного кода:

```go
// НЕБЕЗОПАСНО!
type UnsafeCounter struct {
    value int
}

func (c *UnsafeCounter) Increment() {
    c.value++  // Это НЕ атомарная операция!
}
```

Операция `c.value++` на самом деле состоит из трёх шагов:
1. Прочитать текущее значение
2. Увеличить на 1
3. Записать новое значение

Если две горутины выполняют это одновременно, они могут прочитать одно и то же значение и записать одинаковый результат, "потеряв" один инкремент.

### Решение с Mutex:

```go
// БЕЗОПАСНО
type SafeCounter struct {
    mu    sync.Mutex
    value int
}

func (c *SafeCounter) Increment() {
    c.mu.Lock()
    defer c.mu.Unlock()
    c.value++
}
```

`Lock()` гарантирует, что только одна горутина может выполнять код между `Lock()` и `Unlock()`.

## Пример использования

```go
func main() {
    counter := NewCounter()

    var wg sync.WaitGroup

    // Запускаем 100 горутин, каждая инкрементирует 1000 раз
    for i := 0; i < 100; i++ {
        wg.Add(1)
        go func() {
            defer wg.Done()
            for j := 0; j < 1000; j++ {
                counter.Increment()
            }
        }()
    }

    wg.Wait()

    // Ожидаем: 100 * 1000 = 100000
    fmt.Printf("Итого: %d (ожидалось: 100000)\n", counter.Value())
}
```

## Ожидаемый вывод

```

После 5 инкрементов: 5
После декремента: 4
После Add(10): 14
После Reset: 0 (было: 14)

=== Тест 2: Конкурентный доступ ===
Запущено 100 горутин, каждая делает 1000 инкрементов
Итого: 100000 (ожидалось: 100000)
Тест ПРОЙДЕН!

=== Тест 3: Смешанные операции ===
Инкременты: 50000, Декременты: 50000

```

## Проверка на race condition

Запусти программу с флагом `-race`:

```bash
go run -race main.go
```

Если реализация некорректна, Go выведет предупреждение:
```
WARNING: DATA RACE
```

## Подсказки

- Всегда используй `defer c.mu.Unlock()` сразу после `c.mu.Lock()`
- Каждый метод, который читает или изменяет `value`, должен захватывать мьютекс
- Не забудь, что `Value()` тоже требует блокировки (чтение тоже должно быть защищено)
- Mutex нельзя копировать, поэтому методы должны принимать указатель на Counter

- [ ] Метод `Increment` возвращает новое значение
