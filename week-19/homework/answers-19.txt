Какой HTTP-статус код следует вернуть при успешном создании ресурса через POST? А при успешном удалении через DELETE, если не возвращаем тело ответа?
POST (создание): 201 Created. Это подтверждает, что ресурс успешно создан.
DELETE (без тела): 204 No Content. Означает что все прошло успешно, в ответе ничего не выводится.


Чем отличаются параметры пути (path parameters) от query parameters? Приведи примеры, когда использовать каждый тип.
Path параметры (/users/123): Часть пути. Используются для идентификации конкретного ресурса.
query параметры идут после ?. Используются для фильтрации, сортировки или пагинации.


Что такое идемпотентность HTTP-методов? Какие методы идемпотентны, какие нет? Почему это важно?
Это свойство метода, чтобы запрос изменял состояние базы один раз.
Идемпотентны: GET, PUT (перезапись), DELETE (удаление), HEAD.
НЕ идемпотентны: POST (каждый запрос создает новый ресурс).
Если сеть "моргнула", клиент может безопасно повторить идемпотентный запрос, не боясь создать дубликаты данных.

Почему в REST API рекомендуется использовать единый формат ошибок? Какие поля должен содержать JSON-ответ с ошибкой?
Нужен для того, чтобы фронтенд мог предсказуемо обрабатывать любые сбои. Если формат везде разный, код клиента превращается в кашу из проверок.

Как реализовать пагинацию для списка ресурсов? Какие параметры обычно используются и какая информация возвращается в ответе?
Параметры запроса: page (номер страницы) и per_page (сколько элементов вернуть). Либо limit и offset
