1. Какой HTTP-статус код следует вернуть при успешном создании ресурса через POST? А при успешном удалении через DELETE, если не возвращаем тело ответа?
POST - http.StatusCreated - 201
DELETE - http.StatusNoContent - 204

2. Чем отличаются параметры пути (path parameters) от query parameters? Приведи примеры, когда использовать каждый тип.
path parameters используются для параметров (id, name, и.т.д.), query parameters для пагинации, фильтрации и для сортинга
path parameters - /api/users/{id}
query parameters - /api/products?min_price=100&max_price=1000&page=1&perpage=10&sort=price&order=desc

3. Что такое идемпотентность HTTP-методов? Какие методы идемпотентны, какие нет? Почему это важно?
Идемпотентность - это когда при каком либо запросе, наш ответ не меняется. Например если мы 2 раза сделаем GET запрос, ответ будет абсолютно одинаковый.
А если мы сделаем 2 POST запроса, то у нас в бд будут 2 элемента. Они конечно похожи, но id, created_at будет другой и по факту они отличаются.
GET, PUT, DELETE - идемпотентные. POST, PATCH нет.

4. Почему в REST API рекомендуется использовать единый формат ошибок? Какие поля должен содержать JSON-ответ с ошибкой?
Если проект большой, а формат не единый, это очень не удобно для логирования и в целом тяжко понять где именно в коде ошибка. Недостаточно
знать на каком эндпоинте произошла ошибка.
JSON ответ с ошибкой
{
    error: {
        code: "NOT_FOUND_ERROR",
        message: "user not found"
    }
}

5. Как реализовать пагинацию для списка ресурсов? Какие параметры обычно используются и какая информация возвращается в ответе?
Создаем структур для пагинации с полями page, perPage и в query передаем эти данные.
Например page=10, perPage=20. При каждом запросе мы будем получать 20 элементов начиная с 10 страницы и в конце нужно возвращать доп данные.
