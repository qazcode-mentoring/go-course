1. Чем дженерики отличаются от использования `interface{}`? Какие преимущества они дают?
Когда работаешь с interface{} нужно использовать type assertion, а это не безопасно из за паники.
Дженерики решают эту проблему, помимо этого благодаря дженерикам дублирование кода уменьшается

2. Объясни разницу между ограничениями `any`, `comparable` и `cmp.Ordered`.
any - любые типы
comparable - сравнимые типы !=, ==
cmp.Ordered - типы которые поддерживают <=, >=, <, >

3. Как создать собственное ограничение типа (type constraint)?
В го собственное ограничение типа создается через интерфейс (any, comparable)

type Number interface {
    int | int32 | int64 | float32 | float 64
}

func sum[T Number](x, y T) T {
    return x + y
}

4. Можно ли использовать дженерики с методами структур? Приведи пример.
type Container[T any] struct { Дженерик-структура
    Value T
}

func (c Container[T]) Get() T { Один метод, использующий параметр типа T
    return c.Value
}

5. Когда стоит использовать дженерики, а когда лучше обойтись без них?
Когда есть дублирование кода. Например, когда есть функции которые выполняют одни и те же операции для разных типов или для
структур данных. Не нужно использовать когда функция зависит от 1-2 типов или когда бизнес логика зависит от типа.
