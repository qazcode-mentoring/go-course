Чем дженерики отличаются от использования interface{}? Какие преимущества они дают?
В interface{} можно передать любой тип, но он не будет знать что это за тип. В функции с пустым интерфейсом нужно
делать проверку типа, возможна ошибка во время выполнения.
Generic знает тип на этапе компиляции, не нужно делать проверок.

Объясни разницу между ограничениями any, comparable и cmp.Ordered.
any - любой тип
comparable может быть только тем типом, который поддерживает `==` и `!=`,
а именно: int, string, float, bool, struct
cmp.Ordered может быть только типом, который поддерживает `<`, `>`, `<=`, `>=`
int, float, string


Как создать собственное ограничение типа (type constraint)?
через объединение типов int | int32 | int64 | float32 | float64

Можно ли использовать дженерики с методами структур? Приведи пример.
Да. Нужно указать тип T any для структуры и его значений, затем так же использовать generic в методе

type Box[T any] struct {
	value T
}

func (b *Box[T]) Get() T {
	return b.value
}

Когда стоит использовать дженерики, а когда лучше обойтись без них?
Когда создаем универсальные методы для которых могут меняться типы.
Не стоит использовать если данные всегда определенного типа
